# Deliverable Scaffold Protocol

Creates the starter tree for a new web app under `deliverables/<slug>/`. Runs once per project, right after ARCH.md is approved and before Dev begins implementation.

## When to use

- After CTO writes ARCH.md and it has cleared its debate checkpoint.
- Before CTO writes TASKS.md (because tasks reference concrete file paths).
- Only CTO or Ops should invoke this skill.

## Inputs

1. **slug** — project slug (kebab-case).
2. **stack** — string identifying the chosen stack, e.g. `next-app-router+postgres+tailwind`, `remix+sqlite`, `sveltekit+prisma`.
3. **arch path** — path to ARCH.md for reference.

## Protocol

### Step 1 — Refuse if the directory already exists
Check `deliverables/<slug>/`. If it exists and is non-empty, STOP and return an error. Do not overwrite.

### Step 2 — Create the directory tree
Create `deliverables/<slug>/` and within it:
- `README.md` — project name, one-line description from BRIEF.md, "Generated by AI Outsourcing Studio" footer.
- `package.json` — minimal, matching the stack (name = slug, private: true, correct scripts).
- `.gitignore` — node_modules, build outputs, .env.
- Stack-specific scaffolding:
  - **Next.js**: `app/`, `app/layout.tsx`, `app/page.tsx`, `app/globals.css`, `next.config.mjs`, `tsconfig.json`, `tailwind.config.ts` (if tailwind).
  - **Remix**: `app/`, `app/root.tsx`, `app/routes/_index.tsx`, `remix.config.js`, `tsconfig.json`.
  - **SvelteKit**: `src/`, `src/routes/+page.svelte`, `svelte.config.js`, `vite.config.ts`.
  - **Express/Node**: `src/index.ts`, `src/routes/`, `tsconfig.json`.
- `db/` — empty folder with `.gitkeep` (DBA will fill it).
- `.github/workflows/` — empty folder with `.gitkeep` (Ops will fill it).
- `tests/` — empty folder with `.gitkeep` (QA will fill it).

### Step 3 — Verify
- `package.json` parses as valid JSON.
- All files referenced above exist.
- No placeholder `TODO` strings unaddressed.

### Step 4 — Update state and return
- Update `.company/state.json`: mark `artifacts.CODE = "partial"` and set `active_project` phase to `SCAFFOLDED`.
- Return a short summary listing the created files.

## Anti-patterns

- Do NOT install dependencies (no `npm install`). Scaffolding only creates files. Dev runs installs during implementation.
- Do NOT scaffold features from SPEC.md — only the generic stack skeleton.
- Do NOT scaffold inside `.company/` or at repo root — only inside `deliverables/<slug>/`.
